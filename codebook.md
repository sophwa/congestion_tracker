# Codebook — City Congestion Tracker

All data in this project is **synthetic**, generated by `data/generate_data.py`.
The generation seed is fixed (`random.seed(42)`) so outputs are fully reproducible.

---

## File: `data/locations.csv`

One row per monitored city location. 20 locations total.

| Variable | Type | Description | Example |
|----------|------|-------------|---------|
| `id` | integer | Unique location identifier (1–20) | `1` |
| `name` | string | Human-readable location label | `"Main St & 1st Ave"` |
| `type` | string | Location category: `"intersection"`, `"segment"`, or `"zone"` | `"intersection"` |
| `lat` | float | Latitude in decimal degrees (WGS-84) | `42.444` |
| `lon` | float | Longitude in decimal degrees (WGS-84) | `-76.5019` |

### Location types

| Type | Definition | Count |
|------|-----------|-------|
| `intersection` | A specific road crossing (e.g., Main St & 1st Ave) | 7 |
| `segment` | A road corridor between two reference points | 7 |
| `zone` | A geographic area with aggregated traffic conditions | 6 |

## File: `data/readings.csv`

One row per 15-minute observation at one location. ~26,880 rows covering 14 days (Feb 23 – Mar 8, 2026) × 20 locations × 96 intervals/day.

| Variable | Type | Description | Example |
|----------|------|-------------|---------|
| `id` | integer | Unique reading identifier | `1` |
| `location_id` | integer | Foreign key → `locations.id` | `3` |
| `timestamp` | datetime | UTC observation time (`YYYY-MM-DD HH:MM:SS`) | `2026-02-23 07:15:00` |
| `congestion_level` | float | Composite congestion score, 0 (free flow) to 10 (gridlock) | `6.74` |
| `speed_mph` | float | Estimated vehicle speed in miles per hour (5–45) | `22.3` |
| `volume` | integer | Estimated vehicle count per 15-minute interval | `64` |

### Congestion level thresholds

| Range | Label | Interpretation |
|-------|-------|----------------|
| 0.0 – 3.9 | Low | Free flow; no significant delay |
| 4.0 – 6.9 | Moderate | Noticeable slowdown; minor delays |
| 7.0 – 10.0 | High | Severe congestion; significant delays |

### Data generation model

The congestion level at each location/timestamp is computed as:

```
congestion = base_level × time_of_day_multiplier × day_of_week_multiplier + Gaussian noise
```

Where:
- **`base_level`**: drawn from U(1.5, 4.5) per location (fixed at seed=42)
- **Time-of-day multipliers**: AM peak 7–9 AM → 2.0×, PM peak 4–6 PM → 2.2×, midday → 1.2×, night → 0.3×
- **Day-of-week multipliers**: weekday → 1.0×, Saturday → 0.75×, Sunday → 0.5×
- **Noise**: N(0, 0.5), clamped to [0, 10]

Speed is derived from congestion: `speed = 45 - (congestion/10) × 40 + N(0, 1.5)`, clamped to [5, 45].
Volume scales linearly with congestion and varies by location type (intersections busiest).

## Database Tables (Supabase)

### `locations`

Mirrors `locations.csv`. Same columns and types, with `id` as a `SERIAL PRIMARY KEY`.

### `congestion_readings`

Mirrors `readings.csv`. `id` is `BIGSERIAL PRIMARY KEY`; `location_id` is a foreign key to `locations.id`. `timestamp` is stored as `TIMESTAMPTZ` (UTC).

## API Response Fields

### `/congestion/current` and `/congestion/history`

| Field | Type | Description |
|-------|------|-------------|
| `id` | integer | Reading ID |
| `location_id` | integer | Location ID |
| `location_name` | string | Location name (joined from `locations`) |
| `timestamp` | string | ISO-8601 UTC timestamp |
| `congestion_level` | float | 0–10 congestion score |
| `speed_mph` | float | Estimated speed (mph) |
| `volume` | integer | Vehicle count per 15-min interval |

### `/congestion/summary_data`

| Field | Type | Description |
|-------|------|-------------|
| `location_id` | integer | Location ID |
| `location_name` | string | Location name |
| `location_type` | string | `intersection`, `segment`, or `zone` |
| `avg_congestion` | float | Mean congestion over query window |
| `max_congestion` | float | Peak congestion over query window |
| `min_congestion` | float | Minimum congestion over query window |
| `reading_count` | integer | Number of 15-min readings in window |
| `window_start` | string | ISO-8601 start of aggregation window |
| `window_end` | string | ISO-8601 end of aggregation window |

## Notes

- All coordinates are approximate and represent real Ithaca, NY street locations for geographic plausibility; no real traffic data is used.
- The dataset covers **Feb 23 – Mar 8, 2026** (14 days), with observations every 15 minutes.
- The generation script is deterministic: re-running `generate_data.py` produces identical CSVs.
